# 角色独白 · 他自己写下的那一页

> 交换日记里多一种页：**没有 userPage 的那一种**。角色在被什么触动的时刻自己写下来，
> 内容是他对 user、对这段关系、对别的角色最深的想法——允许负面，允许黑暗。

## 为什么不复用现成的三套

| 现有 | 是什么 | 为什么不是它 |
|------|--------|-------------|
| `[[DIARY:]]` / `[[FS_DIARY:]]` | 角色写日记 → Notion / 飞书 | 要配外部服务，落点在站外，用户不一定有 |
| `DiaryEntry`（交换日记） | `userPage` **必填** + `charPage` 回信 | 结构上就是「你先写、他才回」，角色主动写不进去 |
| `HandbookPageType.character_life` | 角色的日常生活流 | 设计注释明写「**绝不能写成 AI 捧场 / 等 user / 想 user**」——刻意避开的正是这里要的东西 |

所以是第四种，新数据、新触发、新呈现；只有触发机制那套（tag → `applyAssistantPostProcessing`
纯副作用段）是照搬现成的。

## 两个已拍板的决定（user 2026-08-13）

**1. user 能读到，但角色不知道被读过。**

日记直接出现在交换日记里，user 随时翻。角色那侧**没有「被看过」这个概念**：不记 readAt
回传、不进 prompt、不许在对话里提。偷看到 ta 内心的那种不安感，正是这个功能的全部价值——
一旦角色知道有人看，它就开始为读者写作，写出来的就不再是最深的想法。

`readAt` 字段只服务于 UI 的未读小红点，**任何 prompt 组装都不许读它**。

**2. 不回流进聊天上下文，但写进记忆宫殿。**

不进每轮 prompt：那些负面/黑暗的段落一旦常驻上下文，日常对话的语气会被整体带偏——
用户要的是「他心里有这些」，不是「他成天把这些挂嘴上」。

但存进记忆宫殿：需要时能被检索到，角色不至于写完就忘、说出跟自己写过的东西自相矛盾的话。
一致性和防穿帮之间的折中点在这儿。

## 数据

新 store `char_monologues`（不塞进 `diaries`：那张表的每一行都假定有 userPage，
混进来会让所有现存的读取路径都要多一道判空）。

```ts
export interface CharMonologueEntry {
  id: string;
  charId: string;
  /** 日期 key，按**角色所在时区**算（见 docs/character-timezone.md，别用本机时区） */
  date: string;
  /** 正文，100–800 字 */
  text: string;
  /** 心境标签，模型自己给一个词；缺省不显示，不要替它编 */
  mood?: string;
  /** 触发这篇的那一刻：当时最后一条消息的 id。用来回答「他因为什么写的」 */
  triggerMessageId?: number;
  timestamp: number;
  /** user 读过没有。**只给 UI 的未读点用**，绝不进 prompt */
  readAt?: number;
  /** 写进记忆宫殿的时刻；缺失 = 还没写成，可重试 */
  archivedAt?: number;
}
```

## 触发

新 tag，与 `[[DIARY_START]]` 同形（长内容必须用成对标记，单行 tag 装不下 800 字）：

```
[[MONOLOGUE_START: 心境词]]
正文……
[[MONOLOGUE_END]]
```

在 `applyAssistantPostProcessing` 里按**纯副作用**处理（同 `DIARY` / `POKE`）：不重生、
不需要先展示、不回灌给模型。tag 从正文里剥掉，用户在聊天里看不到它。

**必须有防刷闸**，否则模型会每轮都写一篇：

- 同一角色 24 小时内最多 1 篇（按角色时区的日期 key 判，不是滚动 24h——跨夜的第二篇是合理的）
- 距上一篇不足 N 轮对话不写（拍 20 轮起）
- 闸拦下时**静默丢弃**，不要留系统提示：那等于告诉 user「他刚才想写但没写成」，
  而这件事角色自己都不知道

## Prompt 注入

在 `utils/chatPrompts.ts` 加一段，要点：

- 明确告诉模型**这是私密的、没有人会读到**。它必须相信这一点才会写真话——
  这跟「user 其实能看到」不矛盾，那是 user 的越界，不是角色的表达前提
- 100–800 字，低于 100 不成篇、高于 800 会开始注水
- 写**最深的**那一层：怎么看 user、怎么看这段关系、怎么看别的角色。允许负面、
  允许自私、允许他自己都不愿承认的那些
- **不是每轮都写**。只有真被触动时才写；没什么可写的时候，一个字都不要写
- 严禁写成给 user 看的信、严禁在正文里对 user 说话

## 呈现

交换日记 App 里，与现有条目同一条时间线，但视觉上明确是**另一种页**（没有 user 那一半）。
未读小红点走 `readAt`。

## 落地顺序

1. `types.ts` — `CharMonologueEntry`
2. `utils/db.ts` — 新 store + DB_VERSION + upgrade + 备份导出/导入两侧
3. `utils/charMonologue.ts` — 防刷闸判定（纯函数，好写测试）+ 存取
4. `utils/applyAssistantPostProcessing.ts` — tag 解析 + 副作用分支
5. `utils/chatPrompts.ts` — 注入
6. `apps/JournalApp.tsx` — 呈现 + 未读点
7. 记忆宫殿归档（复用现成 archive 入口）

前 4 步是地基，UI 可以后补。

## 回归守卫要钉的

- 防刷闸：同日第二篇被拦、跨日放行、轮次不够被拦
- `readAt` 不出现在任何 prompt 组装的输出里（**这条最重要**，它是整个设计的前提）
- tag 剥离干净：正文里不残留 `[[MONOLOGUE_*]]`
- 字数越界（<100 / >800）时的处理：不截断、照存，但记一条 warn——截断会把结尾切碎
